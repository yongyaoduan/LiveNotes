# LiveNotes 1.0.1

Fixes a regression in 1.0.0 where remembering the recording acknowledgement also skipped the recording name window.

- Every new recording opens the editable name window, including after restarting LiveNotes.
- The first-use acknowledgement stays remembered. It does not reappear for later recordings.
- Recording starts only after clicking Start Recording. Cancelling the name window leaves the saved library unchanged.

Update an existing Homebrew installation:

```bash
brew update
brew upgrade --cask yongyaoduan/livenotes/livenotes
```

Existing recordings, transcripts, and preferences are preserved. This patch continues to use the preview distribution channel: without Developer ID signing, macOS may request system permissions again after an update.

Validation: the regression failed before the fix. All seven related Release UI tests and 103 core tests pass, along with the build-settings and Homebrew cask checks. The UI tests cover custom names, app restart, cancelling the name window, and starting after a recording failure. The recording and translation pipeline is unchanged; native audio validation remains documented in the [1.0.0 validation report](../validation-2026-09-05.md).
